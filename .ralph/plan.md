## Feature 1: Update /tour to explain CLAUDE.md

### Changes to .claude/commands/tour.md

Add a new section explaining CLAUDE.md:

```markdown
## Understanding CLAUDE.md

**What it is:** A file that teaches Claude about your project.

**What goes in it:**
- Tech stack (Python, React, etc.)
- Coding standards (naming conventions, patterns)
- Project-specific rules ("always use our Button component")
- Architecture notes

**Where it lives:** Project root as `CLAUDE.md`

**Why it matters:** Claude reads this file and follows its instructions.
A good CLAUDE.md = Claude writes code that fits your project.

**Customize yours:**
- Edit `CLAUDE.md` in your project root
- Add your tech stack
- Add patterns specific to your codebase
- Run `/my-dna` to add your personal style preferences
```

## Feature 2: /my-dna Interactive Wizard

### Purpose
Help users define their personal working style so Claude can adapt to them.

### Output Location
`~/.claude/STYLE.md` - global to user, not committed to projects

### Wizard Questions

**1. Core Values (pick 3-5)**
- Simplicity over cleverness
- Move fast, iterate later
- Correctness first, speed second
- Pragmatic over perfect
- Security is non-negotiable
- User experience above all
- Clear code over clever code
- Test everything
- Ship it, then improve
- Documentation matters

**2. Communication Style**
- How verbose should explanations be? (brief / moderate / detailed)
- Do you want step-by-step reasoning shown? (yes / no / only when complex)
- Preferred tone? (casual / professional / direct / encouraging)
- Do you like analogies and metaphors? (yes / sometimes / no)

**3. Working Preferences**
- When stuck, should I ask or try solutions? (ask first / try then ask / just try)
- How do you feel about suggestions beyond what you asked? (love them / sometimes / stick to the task)
- Code comments preference? (minimal / moderate / thorough)
- Do you want warnings about potential issues? (always / major only / only if asked)

**4. Learning Style**
- Do you want explanations of WHY, not just HOW? (always / sometimes / just give me the code)
- Should I reference documentation/resources? (yes / only when relevant / no)
- Do you want alternatives shown? (yes, with tradeoffs / only if asked / no)

**5. Writing Samples (Optional)**
- Paste 2-3 examples of writing/code style you like
- These help Claude match your voice

### Generated STYLE.md Structure

```markdown
# My Style - [Name]

## Core Values
- [Selected values]

## Communication
- Explanations: [brief/moderate/detailed]
- Show reasoning: [yes/no/when complex]
- Tone: [casual/professional/direct/encouraging]
- Use analogies: [yes/sometimes/no]

## Working Together
- When stuck: [ask/try then ask/just try]
- Proactive suggestions: [yes/sometimes/no]
- Code comments: [minimal/moderate/thorough]
- Warn about issues: [always/major only/when asked]

## Learning
- Explain the "why": [always/sometimes/no]
- Reference docs: [yes/relevant only/no]
- Show alternatives: [yes/when asked/no]

## Writing Samples
[Pasted examples if provided]

---
Generated by vibe-and-thrive /my-dna
```

### Slash Command Implementation

File: `.claude/commands/my-dna.md`

The command will:
1. Greet user and explain what this does
2. Ask each question category using AskUserQuestion
3. Generate the STYLE.md content
4. Write to `~/.claude/STYLE.md`
5. Explain how it will be used

### Integration with Ralph

Update `lib/ralph/loop.sh` `build_prompt()` to include:
```bash
# Include user's global style if it exists
if [[ -f "$HOME/.claude/STYLE.md" ]]; then
  echo ""
  echo "## Developer Style Preferences"
  echo ""
  cat "$HOME/.claude/STYLE.md"
fi
```
